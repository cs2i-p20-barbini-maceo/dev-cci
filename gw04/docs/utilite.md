# À quoi servent-ils ?

Un workflow, c'est comme un **assistant robot** qui fait des tâches à ta place, automatiquement, sans que tu aies à y penser.

## Les utilisations les plus courantes

### Tester le code automatiquement

Quand tu modifies ton code, le workflow peut lancer des **tests** pour vérifier que tout fonctionne encore. Si quelque chose est cassé, tu es prévenu tout de suite avant que ça parte en production.

> C'est comme un correcteur automatique qui relit ton travail dès que tu sauvegardes.

### Publier un site automatiquement

Dès que tu pousses du code sur GitHub, le workflow peut construire et déployer ton site sur internet. C'est exactement ce qu'on a fait avec **Zensical** : à chaque `git push`, le site se met à jour tout seul.

> C'est comme appuyer sur "envoyer" une seule fois et la lettre arrive partout en même temps.

### Vérifier la qualité du code

Un workflow peut analyser ton code pour détecter les mauvaises pratiques, les fautes de style, ou les oublis. On appelle ça le **linting**.

> C'est comme un correcteur orthographique, mais pour le code.

### Notifier l'équipe

Un workflow peut envoyer un message sur Slack, par email, ou ailleurs pour dire "la mise en production a réussi" ou "il y a une erreur".

### D'autres exemples

- Générer automatiquement une documentation
- Créer une version d'une application (APK, ZIP...)
- Sauvegarder une base de données à intervalles réguliers
